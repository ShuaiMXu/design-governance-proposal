## 本轮决定

面向已有可运行网站的独立开发者，聚焦设计后的诊断、排序、修改或重新生成与验证。先手工交付，再依据真实结果决定工程范围。移出 MVP 的是 Experience Score 总分，不是诊断本身；每个发现仍要有复现路径、证据、任务影响和置信度。

本计划承接上游建议，修正原先“完成整套 MVP 才验证增量价值”的顺序。Issue 原文未统一改写前，本计划记录拟执行范围；不将尚未完成的实验标为通过。

## 执行分工与输入

我负责协议、样本材料整理、证据记录、对照执行的技术准备和结果分析。项目持有人提供真实项目与可复现流程；用户负责引入目标受访者与独立评审，或明确授权后再安排联系。当前没有授权主动向任何人发送邀请。

项目代码修改仅用于独立实验分支，并以三组相同起点运行；它不等于实现本产品。真实项目尚未选定，不用当前的商业提案页冒充独立开发者产品样本。

## 判断边界

G1 的口头付费意愿是信号，不是收入。G2 的单项目对照是探索性结果，不证明跨项目优势；单次运行不能支撑中位数时间结论。G3 把运营者人工时间计入成本，不能因创始人免费劳动而显示盈利。已有 ≥30%/4-of-5 门槛保留，具体计算方式见协议；不在看到结果后改标准。

选定项目时优先避开 C 组操作者参与过开发的项目。用自己的项目做对照会让 C 组带入上下文包之外的代码结构与历史决策，系统性抬高结果；无法避开时按协议登记先验关系并对该次结论折价，不作为跨项目证据。
